# Plan: Album Cover Art Selection

**Branch:** `feature/album-cover-art-selection`  
**Test library:** `/mnt/storage/music`

---

## Overview

Lidarr currently fetches a single album cover image automatically from its metadata
provider (LidarrAPI/SkyHook) with no way for the user to choose an alternative. This
feature adds a selection screen to every album page where the user can browse
candidate cover images aggregated from multiple sources and pin one as the active
cover. The chosen image survives metadata refreshes.

Cover art is sourced from a **pluggable multi-provider architecture**. Each provider
is independently enabled and, where required, independently credentialed. If any
single provider is unavailable, the others continue to supply results.

---

## Providers

| Provider | Always on | Credentials | Max image size | Notes |
|---|---|---|---|---|
| **iTunes** | ✅ | None | ~4000px | Best quality; zero friction; no auth |
| **MusicBrainz / CAA** | ✅ | None | Up to ~1200px+ | Exact MBID lookup; no fuzzy search; 4 s timeout; response cached |
| **Discogs** | Optional | Personal Access Token | ~1600px | Best for physical/vinyl releases |
| **Spotify** | Optional | Client ID + Secret | 640px | Good breadth; development mode = 5-user cap |
| **Last.fm** | Optional | API Key | ~300px | Low image quality; useful as fallback only |

**Bandcamp** was considered and rejected: it has no public API — any implementation
would require scraping, which violates their ToS and is fragile.

### iTunes
The iTunes Search API (`itunes.apple.com/search`) requires no authentication and is
the only always-on provider alongside MusicBrainz. It returns an `artworkUrl100`
field whose dimension suffix can be mechanically replaced to retrieve the master
image (typically 3000–4000 px).

### MusicBrainz / Cover Art Archive
Lidarr already stores `Album.ForeignAlbumId` (MusicBrainz Release Group ID) and
`AlbumRelease.ForeignReleaseId` (MusicBrainz Release ID) for every album, so no
text search is needed — the query is always an exact ID lookup:

```
GET https://coverartarchive.org/release-group/{Album.ForeignAlbumId}
```

If the aggregation endpoint returns a non-2xx response, fall back to per-release
queries using the `ForeignReleaseId` values already present in the database. A 4-second
timeout applies to each CAA call. Successful responses are cached for 24 hours
against the `ForeignAlbumId` to insulate against CAA's known intermittent
availability issues.

### Discogs
Requires a Personal Access Token (PAT) generated by the user from their Discogs
account settings — no app registration needed. The Discogs search API returns
releases whose per-release endpoint (`/releases/{id}`) carries the full `images[]`
array, necessitating a two-call chain per result. Rate limit: 60 req/min
authenticated. A `User-Agent` header identifying the application is mandatory.

### Spotify
Requires the user to register a Spotify Developer App and supply a `client_id` +
`client_secret` in Lidarr's settings. The app operates in **development mode**
(max 5 allowlisted users), which is correct for a self-hosted instance. As of
May 2025, Extended Quota Mode requires Spotify approval and 250k MAUs — out of
scope. OAuth2 Client Credentials tokens expire after 3600 s and must be refreshed
automatically. Maximum image size is 640 × 640 px. Spotify's Developer Policy
requires that cover art displayed in the UI link back to the album on Spotify.

### Last.fm
Requires a free API key registered at `last.fm/api`. Image quality is low (≤ 300 px)
and highly variable — many entries return a placeholder. Recommended only as a
fallback when other providers return nothing. Must credit Last.fm in the UI.

## Architecture

### Storage model

Lidarr uses a **two-layer model**: the database stores only URL strings; image bytes
live exclusively on the filesystem.

#### Database layer — URLs only

`Album.Images` is a `TEXT` column in the `Albums` table holding a JSON-serialised
`List<MediaCover>`. Each `MediaCover` object carries:

```
Url        string   — initially the remote origin URL from SkyHook
RemoteUrl  string   — preserved copy of the original remote URL
CoverType  enum     — Cover (6), Poster (1), Fanart (3), …
Extension  string   — parsed from the URL on assignment (.jpg / .png)
```

The database **never stores image bytes**. It stores only the URL that was used as
the download source.

#### Filesystem layer — image bytes and resizes

When `EnsureAlbumCovers()` runs it downloads the URL stored in `Album.Images` and
writes the result to:

```
{appData}/MediaCover/Albums/{albumId}/cover.jpg       ← full resolution
{appData}/MediaCover/Albums/{albumId}/cover-500.jpg   ← resized
{appData}/MediaCover/Albums/{albumId}/cover-250.jpg   ← resized
```

`{appData}` defaults to `~/.config/Lidarr/` on Linux. `albumId` is the internal
integer primary key (not the MusicBrainz MBID).

Before downloading, `EnsureAlbumCovers()` issues an `HTTP HEAD` against the source
URL and compares `Last-Modified` + `Content-Length` against the on-disk file. The
download is skipped when these match, so the filesystem is the cache.

#### Serving

`MediaCoverController` handles `GET /MediaCover/Albums/{albumId}/cover.jpg` by
calling `PhysicalFile()` directly from disk — no database read occurs at serve
time. If a resized variant is missing it falls back to the full-size file.

Before `AlbumResource` is returned by the API, `ConvertToLocalUrls()` rewrites
each `MediaCover.Url` from its remote origin to the local `/MediaCover/…` path,
so the frontend only ever sees local URLs.

### How cover art flows today

```
SkyHookProxy.GetAlbumInfo()
  └─ MapImage()               remote URL → MediaCover { CoverType=Cover, Url }
       └─ Album.Images[]      stored as URL-string JSON blob in Albums table

RefreshAlbumService
  └─ EnsureAlbumCovers()
       ├─ HEAD remote URL → compare Last-Modified + Content-Length vs disk
       ├─ (if changed) download → {appData}/MediaCover/Albums/{albumId}/cover.jpg
       └─ generate cover-500.jpg, cover-250.jpg resizes

MediaCoverController
  └─ GET /MediaCover/Albums/{id}/cover[-500|-250].jpg
       └─ PhysicalFile() straight from disk

AlbumControllerWithSignalR
  └─ ConvertToLocalUrls()     rewrites Url → /MediaCover/Albums/{id}/cover.jpg
       └─ AlbumResource.Images[]   what the frontend receives
```

### Where user selection fits in

```
[new] CoverArtAggregatorService
  ├─ ItunesCoverArtProvider       GET itunes.apple.com/search
  ├─ MusicBrainzCoverArtProvider  GET coverartarchive.org/release-group/{mbid}
  ├─ DiscogsCoverArtProvider      GET api.discogs.com/database/search  (if PAT set)
  ├─ SpotifyCoverArtProvider      GET api.spotify.com/v1/search        (if creds set)
  └─ LastFmCoverArtProvider       GET ws.audioscrobbler.com/2.0/       (if key set)
       └─ returns merged, deduplicated List<CoverArtCandidate>

[new] GET /api/v1/albums/{id}/coverartcandidates
  └─ returns candidate list; ThumbnailUrls rewritten through proxy endpoint

[new] PUT /api/v1/albums/{id}/coverart  { "coverUrl": "…" }
  ├─ Album.UserSelectedCoverUrl = coverUrl   (URL string persisted to DB)
  ├─ EnsureAlbumCovers() downloads chosen URL to disk
  │    └─ {appData}/MediaCover/Albums/{albumId}/cover.jpg  (+ resizes)
  └─ SignalR broadcast → ConvertToLocalUrls() rewrites to /MediaCover/… path
       └─ frontend sees updated cover with no special serving logic

[new] DELETE /api/v1/albums/{id}/coverart
  └─ clears UserSelectedCoverUrl, EnsureAlbumCovers() re-downloads SkyHook default

RefreshAlbumService (guarded)
  └─ if Album.UserSelectedCoverUrl is set → preserve it across refreshes
```

#### `ItunesCoverArtProvider.cs`

- `GET https://itunes.apple.com/search?term={artist}+{album}&entity=album&limit=25`
- No auth. Always enabled.
- Rewrites `artworkUrl100` → `artworkUrl3000` (replace `100x100bb` in URL with
  `3000x3000bb`) for full-resolution image URL.
- Thumbnail = `artworkUrl100` as-is.

#### `MusicBrainzCoverArtProvider.cs`

- Always enabled.
- **Fast path**: `GET https://coverartarchive.org/release-group/{foreignAlbumId}`
  with a 4-second timeout.
- **Fallback path**: if the fast path returns non-2xx or times out, iterate
  `foreignReleaseIds` (from `AlbumRelease` rows already in the DB) and call
  `GET https://coverartarchive.org/release/{releaseId}` for each, collecting
  whatever responds within 4 seconds per call.
- Successful responses are cached in-memory keyed by `foreignAlbumId` for 24 hours.
- Sorts results: front images first, approved first within each group.

#### `DiscogsCoverArtProvider.cs`

- Enabled only when `DiscogsPersonalAccessToken` is set.
- Search: `GET https://api.discogs.com/database/search?artist={artist}&release_title={album}&type=release&token={pat}`
- Per-result fetch: `GET https://api.discogs.com/releases/{id}` to obtain the
  full `images[]` array.
- Throttle to ≤ 60 req/min. Use `X-Discogs-Ratelimit-Remaining` response header
  to self-regulate.
- `User-Agent` header must be set to `Lidarr/{version} (https://lidarr.audio)`.

#### `SpotifyCoverArtProvider.cs`

- Enabled only when both `SpotifyClientId` and `SpotifyClientSecret` are set.
- Token acquisition: `POST https://accounts.spotify.com/api/token` using Client
  Credentials flow. Token is cached in memory until 60 seconds before its
  `expires_in` deadline, then proactively refreshed.
- Search: `GET https://api.spotify.com/v1/search?q=artist:{artist}+album:{album}&type=album&limit=20`
- Returns images at all three available sizes (640 / 300 / 64 px); exposes the
  640 px as `ImageUrl` and 300 px as `ThumbnailUrl`.
- Attribution: `ReleaseUrl` is populated with the Spotify album URL so the
  frontend can display the required link-back.

#### `LastFmCoverArtProvider.cs`

- Enabled only when `LastFmApiKey` is set.
- Search: `GET https://ws.audioscrobbler.com/2.0/?method=album.search&album={album}&artist={artist}&api_key={key}&format=json`
- Filters out results where the image URL resolves to Last.fm's generic placeholder
  hash (`2a96cbd8b46e442fc41c2b86b821562f`).
- Exposed as low-priority fallback: candidates from this provider are appended
  after all others in the aggregated list.

### Phase 5 — Aggregator service

**New file:** `src/NzbDrone.Core/MediaCover/CoverArtAggregatorService.cs`

```csharp
public interface ICoverArtAggregatorService
{
    Task<List<CoverArtCandidate>> GetCandidatesAsync(Album album, CancellationToken ct);
}
```

Implementation:

1. Collects all `ICoverArtProvider` instances via DI injection.
2. Fans out to all enabled providers **in parallel** using `Task.WhenAll`.
3. Merges results; deduplicates by `ImageUrl` (exact string equality after
   URL normalisation).
4. Sorts the merged list: iTunes and MusicBrainz results first (highest quality),
   then by image width descending within each tier, Last.fm last.
5. Returns up to 100 candidates. The UI paginates from there.

### Phase 6 — Guard the refresh pipeline

**File:** `src/NzbDrone.Core/Music/Services/RefreshAlbumService.cs`

In `UpdateEntity()`, guard the cover download step:

```csharp
if (local.UserSelectedCoverUrl.IsNullOrWhiteSpace())
{
    // Normal path: sync from remote metadata.
    if (remote.Images.Any() && !local.Images.SequenceEqual(remote.Images))
    {
        if (_mediaCoverService.EnsureAlbumCovers(remote))
            result = UpdateResult.UpdateTags;
    }
}
else
{
    // User has pinned a cover: re-download their choice so resize
    // caches stay fresh, but do not overwrite UserSelectedCoverUrl.
    if (_mediaCoverService.EnsureAlbumCovers(local))
        result = UpdateResult.UpdateTags;
}
```

**File:** `src/NzbDrone.Core/MediaCover/MediaCoverService.cs`

In `EnsureAlbumCovers()`, add the override path before the existing download loop:

```csharp
public bool EnsureAlbumCovers(Album album)
{
    var coverImages = album.Images
        .Where(e => e.CoverType == MediaCoverTypes.Cover)
        .ToList();

    if (album.UserSelectedCoverUrl.IsNotNullOrWhiteSpace())
    {
        coverImages = new List<MediaCover>
        {
            new MediaCover(MediaCoverTypes.Cover, album.UserSelectedCoverUrl)
        };
    }

    // … existing download / resize logic, now operating on coverImages …
}
```

On download failure for a user-selected URL (404 / connection error after retries),
log a warning, clear `UserSelectedCoverUrl`, and fall back to the first image in
`album.Images` with `CoverType == Cover`.

Once `EnsureAlbumCovers()` completes, the image is on disk at
`{appData}/MediaCover/Albums/{albumId}/cover.jpg`. `ConvertToLocalUrls()` and
`MediaCoverController` serve it through the standard `/MediaCover/Albums/{id}/…`
path with no additional code — identical to the existing pipeline.

### Phase 7 — API endpoints

**File:** `src/Lidarr.Api.V1/Albums/AlbumController.cs`

Inject `ICoverArtAggregatorService` and `IAlbumService` and add three new actions:

#### `GET /api/v1/albums/{id}/coverartcandidates`

- Loads the album; collects all `AlbumRelease.ForeignReleaseId` values for it.
- Calls `ICoverArtAggregatorService.GetCandidatesAsync(album, ct)`.
- Rewrites each `ThumbnailUrl` through the cover proxy endpoint (Phase 8) so
  the browser can display images from external CDNs without CORS issues.
- Returns HTTP 200 with `List<CoverArtCandidateResource>`. An empty list is
  valid — not a 404.

#### `PUT /api/v1/albums/{id}/coverart`

Request body: `AlbumCoverArtResource { string CoverUrl }`.

- Validates `CoverUrl` is a non-empty, well-formed HTTPS URL.
- Sets `album.UserSelectedCoverUrl = resource.CoverUrl`.
- Persists via `_albumService.UpdateAlbum(album)`.
- Calls `_mediaCoverService.EnsureAlbumCovers(album)` synchronously to download
  and generate resizes immediately.
- Broadcasts `ModelAction.Updated` via SignalR.
- Returns HTTP 202 Accepted.

#### `DELETE /api/v1/albums/{id}/coverart`

- Clears `UserSelectedCoverUrl` (sets to `null`).
- Calls `EnsureAlbumCovers()` to re-download the SkyHook default.
- Broadcasts SignalR update.
- Returns HTTP 202 Accepted.

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Cover Art Archive is intermittently unavailable | 4 s timeout per CAA call; 24 h response cache; other providers continue serving results unaffected |
| User-selected URL goes dead after pinning | On `EnsureAlbumCovers()` download failure, clear `UserSelectedCoverUrl`, fall back to SkyHook default, log a warning |
| Metadata refresh overwrites user choice | Guard in `RefreshAlbumService.UpdateEntity()` (Phase 6) prevents this |
| Spotify 5-user dev mode cap | Documented clearly; each user registers their own app; standard self-hosted pattern |
| Spotify cover art attribution requirement | `ReleaseUrl` is populated and the frontend must render it as a link |
| Discogs two-call rate limit pressure | Throttle using `X-Discogs-Ratelimit-Remaining` header; return partial results rather than waiting |
| Proxy endpoint abused to fetch arbitrary URLs | Strict `AllowedHosts` set covering only known provider CDN origins |
| Fuzzy search returning wrong albums (Spotify / iTunes / Last.fm / Discogs) | Results are presented to the user, not auto-applied; `ReleaseTitle` and `ReleaseUrl` give context for manual verification |
| Spotify token expiry during a slow request | Token is proactively refreshed 60 s before expiry; 401 responses trigger an immediate re-fetch |
| Last.fm placeholder images polluting results | Filter by known placeholder image hash before including in candidate list |

```js
  isSaving:    false,   // true while PUT or DELETE is in-flight
  saveError:   null,
  items:       []       // List<CoverArtCandidateResource>
}
```

#### Actions

| Exported thunk/action | HTTP call | Purpose |
|---|---|---|
| `fetchCoverArtCandidates({ albumId })` | `GET /album/{id}/coverartcandidates` | Load candidate grid |
| `selectCoverArt({ albumId, coverUrl })` | `PUT /album/{id}/coverart` `{ coverUrl }` | Pin chosen cover |
| `resetCoverArt({ albumId })` | `DELETE /album/{id}/coverart` | Revert to SkyHook default |
| `clearCoverArtCandidates()` | — | Clear state on modal close |

`fetchCoverArtCandidates` uses `createFetchHandler(section, '/album')` with `id`
set to `${albumId}/coverartcandidates`.

`selectCoverArt` and `resetCoverArt` are hand-written thunks (like
`TOGGLE_ALBUM_MONITORED` in `albumActions.js`): after a successful response they
dispatch `updateItem({ section: 'albums', ...responseData })` so the album's
`images` array refreshes in-place in the Redux store and `AlbumCover` re-renders
immediately without a full page reload.

`clearCoverArtCandidates` resets the section back to `defaultState` exactly like
`clearOrganizePreview` does.

**Register in:** `src/Store/Actions/index.js` — add
`import * as coverArt from './coverArtActions'` and include `coverArt` in the
exported array.

#### `SelectCoverArtModalConnector.js`

Connects to `state.coverArt`. Pattern: `OrganizePreviewModalContentConnector`.

- `componentDidMount`: dispatches `fetchCoverArtCandidates({ albumId })`.
- `componentWillUnmount`: dispatches `clearCoverArtCandidates()`.
- `onSelectPress(coverUrl)`: dispatches `selectCoverArt({ albumId, coverUrl })`
  then calls `onModalClose()`.
- `onResetPress()`: dispatches `resetCoverArt({ albumId })` then calls
  `onModalClose()`.
- Maps `state.coverArt` → `{ isFetching, isPopulated, error, isSaving, items }`.

#### `SelectCoverArtModalContent.js`

Renders three states:

1. **Loading** (`isFetching && !isPopulated`):
   `<LoadingIndicator />` centered in the modal body.

2. **Empty / error** (`isPopulated && items.length === 0`, or `error`):
   `<Alert kind={kinds.WARNING}>{translate('NoCoverArtCandidatesFound')}</Alert>`

3. **Grid** (`isPopulated && items.length > 0`):
   A `className={styles.grid}` `<div>` containing one card per candidate:

   ```
   ┌───────────────────────┐
   │   [source badge]      │  ← <Label> top-left, e.g. "iTunes"
   │                       │
   │   <img thumbnail>     │  ← 160×160, object-fit: cover
   │                       │
   │ resolution  [Select]  │  ← "3000×3000" + SpinnerButton
   └───────────────────────┘
   ```

   The thumbnail `src` is the proxied URL:
   `/api/v1/MediaCover/proxy?url=${encodeURIComponent(candidate.thumbnailUrl)}`

   Source badge colour mapping:

   | Source | `kinds` value |
   |---|---|
   | iTunes | `kinds.PRIMARY` |
   | MusicBrainz | `kinds.INFO` |
   | Discogs | `kinds.WARNING` |
   | Spotify | `kinds.SUCCESS` |
   | Last.fm | `kinds.DEFAULT` |

   If `candidate.releaseUrl` is present, the card shows a small external-link
   icon (`icons.EXTERNAL_LINK`) next to `candidate.releaseTitle` linking to
   `candidate.releaseUrl` (satisfies Spotify attribution requirement).
